# Decisions

| Date | Decision | Reason |
|---|---|---|
| 2026-11-18 | Collect all routes | Collection cost is the same, and data not collected cannot be recovered later |
| 2026-11-18 | Poll vehicle positions and trip updates every 20 s, alerts every 5 min, around the clock | About 0.1% of the host's stated rate limit; off-hours responses are part of the record |
| 2026-11-18 | Collector on Supabase (scheduled edge function), pipeline and archive on GitHub | No server to run; sub-minute scheduling; no cost |
| 2026-11-18 | Store raw responses before parsing; treat them as the source of truth | Parsing can be redone; collection cannot |
| 2026-11-18 | Keep every field the feed sends, including `occupancy_status` | Full transparency; it is a per-vehicle category, not data about a person |
| 2026-11-18 | Publish raw and derived data from the first day | Visibility; data sits in Releases so it can be withdrawn if the agency objects |
| 2026-11-18 | Identify the collector by project name and repository URL in the User-Agent | Lets the host see who is polling and where to complain |
| 2026-11-18 | On-time window: 1 minute early to 5 minutes late, at true timepoints only | Common agency convention; Passio schedule times at other stops are interpolated |
| 2026-11-18 | One collector function for real-time and static downloads | Fewer parts to deploy than the two functions first planned |
| 2026-11-19 | Keep polling trip updates every 20 s although they refresh about once a minute | Cheap, and the refresh rate is itself something to measure; revisit after a week of data |
| 2026-11-19 | Limit prediction-error figures to trips matched to a reporting vehicle | The trip-update feed also lists upcoming trips that have no bus yet |
| 2026-11-19 | Use the feed's speed field to detect stationary buses | Present on every vehicle in the daytime check |
| 2026-11-19 | The collector checks its shared secret by asking the database, not from a function environment variable | Setup needs no manual step, and the secret never leaves the database |
| 2026-11-19 | Download the Passio static GTFS twice a day (2:15 AM and 8:30 AM Pacific) | The zip was incomplete at night and complete in the morning; sampling both times measures that |
| 2026-11-19 | Collection started 21:24:41 UTC | First logged fetch |
| 2026-11-19 | Archive complete Pacific days shortly after midnight, not the same evening | A day is not finished until midnight; off-hours fetches belong to it |
| 2026-11-19 | Collector version 0.2.0 from 21:37 UTC | Adds the prune step; fetching is unchanged |
| 2026-11-19 | Parsed tables store runs of unchanged values, not one row per fetch | Polling every 20 s repeats most values; runs keep every change and how long each value was seen, at a fraction of the size |
| 2026-11-19 | Parsed tables are built from the archived raw file, not from the collector | Every derived row then traces to a published file and its hash |
| 2026-11-19 | Parsed tables go to their own `parsed-YYYY-MM` releases, rebuilt when the table code version changes | Raw files never change; derived files can be regenerated |
| 2026-11-19 | Static GTFS versions are identified by the hash of every file except `feed_info.txt` | Passio rewrites its feed_info dates daily and Trillium stamps generation time; neither is a schedule change |
| 2026-11-19 | Each service day is pinned to the first complete download that day, else a matching incomplete download, else the latest earlier complete download | Uses the schedule as published for that day where possible, and records which rule applied |
| 2026-11-19 | Identify true timepoints by route and stop, not trip by trip | The Passio and Trillium schedules differ (route 1 weekdays: 68 trips from 03:35 in Passio, 43 from 03:45 in Trillium), so trips cannot be paired; how far they differ is reported as schedule agreement |
| 2026-11-19 | Stop crosswalk: same `stop_code` within 150 m, else nearest stop within 60 m | Codes match for most stops; a few shared codes point to stops kilometers apart; many NAS Whidbey stops have no code in Passio |
| 2026-11-19 | Quality metrics are written to the `data` branch as one JSON file per day plus a headline CSV | Small, diffable, readable by the site without a server |
| 2026-11-19 | Scheduled trips come from the Passio calendar even on holidays; Trillium's holiday removals are reported alongside | Passio is the schedule the real-time feed follows; mixing calendars would hide the disagreement |
| 2026-11-19 | Treat Passio as the schedule in effect; use Trillium only for timepoint flags, and check those against the published timetables | Island Transit's website timetable (effective 2026-09-27) matches Passio on the route 1 trips checked and not Trillium, whose calendar dates from 2025-06-01 |
| 2026-11-19 | Keep the printed timetable stops (service guides effective 2026-09-27) in `reference/` and check timepoints against them | They are the agency's published timepoints; the Trillium feed is out of date. 93% of matched printed timepoints are also Trillium timepoints |
| 2026-11-20 | True timepoints come from the printed timetables, not the Trillium feed (Davin's decision) | They are what the agency publishes; Trillium's schedule is out of date. Trillium's flags stay as a comparison. A new reference file is needed at each service change |
| 2026-11-20 | Printed timetable names that fit no single Passio stop are left out, not guessed | A wrong timepoint would put wrong numbers in on-time figures; the count of unresolved names is published daily |
| 2026-11-20 | Track a trip from the first position near its start, not the first position carrying its id | On loop routes the bus shows the next trip id while finishing the previous loop; anchoring on those positions misplaced whole trips |
| 2026-11-20 | Report stop events and on-time figures from the first day, labelled experimental | Visibility; the method and its limits are published, and field validation follows |
| 2026-11-20 | Quality metrics from stop events (`quality/0.2.0`): stop-level coverage, off-shape share, prediction error, unassignable trips, jitter, vehicles missing against 30 days | Methods listed them; stop events now exist. Labelled experimental with the events |
| 2026-11-20 | Predictions whose clock time falls on another Pacific day than the trip are counted separately and left out of prediction error | The feed sends no `start_date`; about 1 to 2% of short-horizon predictions on 2026-11-19 pointed at the next day's run of the same trip id, with errors of 6 to 19 hours that would swamp the means |
| 2026-11-20 | Place stops on shapes by ordered best fit over every pass, not nearest point ahead (`events/0.2.0`) | On loops a stop beside a road used again at the end of the loop was placed at the end, taking every later stop with it (routes 1C and 2C) |
| 2026-11-20 | Collapse shape segments drawn forth, back and forth again; report the meters removed | Passio's 1C shapes repeat every segment, making them 76 km for a 45-minute loop; distances along the shape were about three times the distance driven |
| 2026-11-20 | Let tracking move past parts of the shape a bus does not drive, once two consecutive positions agree; give those stops no time | 1C and 2C buses leave out loops that the published shapes include (for example Cama Beach and Russell Rd on 1C); before, tracking stopped there and the rest of the trip was lost |
| 2026-11-20 | Run validation checks 2 and 3 (feed stop-sequence agreement, segment travel times) every night and publish them beside the on-time figures | They need no field data, so the method's agreement with the feed is visible from day one; field timing (check 1) still decides when the experimental label comes off |
| 2026-11-20 | Several scheduled nightly attempts a day, a watchdog catch-up that dispatches the nightly job, and site deploys only when data changed | GitHub never started the first 08:35 UTC nightly run and fired the 30-minute watchdog only twice in its first day; every nightly step handles pending days only, so extra attempts are harmless |
| 2026-11-20 | Start the nightly archive and watchdog from pg_cron through GitHub's dispatch API, keeping the GitHub schedules as a fallback | GitHub skipped the first 08:35 UTC nightly run and fired the 30-minute watchdog once in about 12 slots; the first day was archived by a manual run at 09:10 UTC. pg_cron already runs the collector reliably. Costs nothing; needs a repository-only token in Vault |
| 2026-11-20 | Randomness of gaps (`quality/0.3.0`, `gaps/0.1.0`): store each day's trip-level coverage rows, publish rates from day one, fit a Firth logistic model from 14 days and 30 unobserved trips | Rates are descriptive and safe on little data; a model on one partial day (161 trips, 5 unobserved) would be noise. | 2026-11-20 | Field check: observers time the bus at 40 m before and 40 m past the stop, on sheets generated from the schedule with trip ids filled in; scored nightly | The same definition as the inferred times, so a difference measures the method, not a change of definition. | 2026-11-21 | Remove the "experimental" label from stop events and on-time figures; show a plain note on what was checked (Davin's decision) | Checks 2 and 3 pass on every route daily and the route 60 spot check agreed within 2 to 7 s.
